# Pinned local CPU model comparison

The manual `comparePinnedCandidates` input of **Android verification** runs six independent Ubuntu 24.04 matrix jobs. Each downloads one public, revision/SHA-pinned LiteRT artifact into disposable runner storage and executes local native inference. The jobs share the same invented inputs, production field instruction, JSON schema, parser and scorer. They do not send document data to a hosted inference service or activate an application model.

The manifest is `scripts/model-batch-manifest.json`: Gemma4 E2B, MiniCPM5 1B, Qwen2.5 1.5B, Phi4 mini, SmolLM2 360M and SmolLM3 3B INT4. Quantizations differ because these are the actual published compatible bundles. The 360M model is a lower-bound control. Publisher cards, artifact hashes, actual runner resources and native library hash are retained in each receipt. Published conversion provenance does not imply an independently reproducible conversion or physical Android compatibility.

All jobs use `litert-lm-api==0.17.1`, Linux CPU, two threads, context 4096, output limit 1024, topK 1, topP 0.95, temperature 0, seed 42, thinking disabled and the bundle's unmodified template. The fixed sampler and Python/Linux binding are a research configuration; the Android provider leaves sampler defaults to its binding. Bundle handling of thinking flags is runtime behavior; complete responses are preserved. No candidate-specific prompt, template, seed or retry is selected by scores.

The existing 16 `LiteRtEvaluationFixtures` cases are consumed synthetic development controls: 13 positive field cases, two unsafe original-input controls, and one missing-subject preparation rejection. The two unsafe prepared inputs are sent directly to the native component intentionally. The production input gate rejects partial pages; unverified missing teacher fields must still fail the final evidence validator. Preparation rejection is separate from generation. Missing setup, initialization, process, resource or per-call outputs remain explicit unavailable/error rows in the planned denominator. Wrong answers on unsafe inputs do not count as correct negatives.

The build extracts the unchanged private Android provider instruction/schema/strict parser under both Provider and fixture SHA guards. Any change requires a reviewed fingerprint update. Inference export contains no expected field assignment. Scoring regenerates the original immutable fixtures, checks independent literal values, strict source-ID grounding, complete metadata-normalized `RecoveryResult` equality, unchanged `RecoveryValidator`, and `RecoveryAnalysis.convert`. Separate complete positive Rules/Engine controls assert zero provider calls. All these fixtures are Rules resolved: component accuracy does not establish useful model recovery.

Models and native caches are removed after each job. Complete raw outputs and receipts travel through SHA-checked gzip/Base64 console records (`TAKUPOKE_MODEL_BATCH_*`); persistent Actions artifacts and caches are not used. Resource guards terminate only the owned child. Receipt hashes and actual job IDs identify an execution, and prior failed experiments stay separate.

Run harness checks locally with `python3 scripts/test_model_batch.py` and `./gradlew :model-evaluation:test :model-evaluation:installDist`. The generated CLI supports `export corpus.json` and `score native.json score.json`.

This comparison does not approve a catalog entry. Even a perfect component score would still require independently frozen heldout ordinary/exam/return coverage, genuinely unresolved useful recovery cases, and target-device memory/backend checks. No physical Android device was available in this session.

The isolated `research/gemma-prompt-compare-20261004` branch also runs **Gemma fixed prompt comparison**: two independent concurrent jobs, same pinned Gemma bundle, exact same sixteen-case corpus bytes, schema, native settings and core scorer. `baseline` uses the extracted production instruction; exactly one `clear_v1` research instruction explicitly separates readable PRESENT bodies, verified EMPTY and conditional unknown states, and confines evidence to original body atoms. Each actual call records its selected instruction SHA. This is the user's requested controlled prompt diagnostic, not a production instruction change or an independently blind holdout. Unknown original fields remain unknown; no expected assignment enters either prompt.

The same isolated branch runs **Gemma exact reference prompt comparison** for only `reference_v1`, the user's supplied instruction copied verbatim (SHA `23f711aa564233963fd1a259d0403b45e3d891d6903fc0009dd6853a32371d9c`, 3927 UTF-8 bytes, no terminal newline). The corpus, model, schema, sampler and core scorer stay identical to the completed baseline/clear conditions. This third condition is compared with those retained receipts; completed conditions are not rerun. Missing or changed reference bytes fail closed before native allocation.

The isolated `research/android-micro-fields-20261004` branch adds one bounded **single-field ID-copy compliance** cohort for the same pinned Gemma4 E2B and Qwen2.5 1.5B bundles. It reuses the completed exact-reference whole-cell results; no full-cell generation is rerun. The original sixteen fixture definitions and corpus fingerprint stay fixed. Actual production Rules/Engine/Validator/formal controls resolve all thirteen positive cells (42 field obligations) with zero provider calls. The original incomplete page, unverified teacher absence and missing subject are deterministic preflight rejections and earn no model-negative credit.

For the explicitly forced component control, the application derives each role's ordered body candidates from original certified scope containment or fixed bindings, excludes all label/separator IDs, and determines PRESENT or verified teacher/room EMPTY outside the model. Every field is already determined; the prompt asks only to copy the supplied candidate IDs. This measures unnecessary copy/JSON compliance, with zero genuine AI-choice or useful recovery cases. All original cell IDs remain in the grammar enum, so labels and other roles are not removed from the syntactic allowlist. Returned unknown, duplicate or reordered IDs are rejected without sorting or repair. Duplicate JSON keys, unquoted/nonstring values, nested shapes, trailing JSON, more than 48 items or more than 16 KiB UTF-8 output are rejected by the strict streaming parser. Missing returned IDs do not imply EMPTY.

All 42 positive field calls are scheduled; native attempts, returned outputs and unstarted rows are recorded separately under the resource guard. Three original preflight rows produce 45 planned rows. Partial returned fields and whole cells retain distinct assessed and execution-unassessed denominators. Actual assembled state/evidence goes through the unchanged core grounding, Validator, full-cell result and formal checks. The two independent CPU runners share the existing sampler/context/output limits and use a 900-second owned-child guard. No model is activated or approved by this diagnostic. The CLI commands are `export-micro corpus.json` and `score-micro native.json score.json` from the repository root.
